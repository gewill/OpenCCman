## 本轮实现

- 移除强制 AX 选区读取，使用不抑制本地输入的私有 CGEvent source 经 HID 发送复制/粘贴。
- 来源 PID 必须仍在前台；以硬件输入活动计数捕捉操作期间的键盘、点按、拖动、滚轮变化；等待超过 5 秒取消。
- 转换后、粘贴前再次复制完整选文并比较；剪贴板归属变化、无法复制、选文变化、来源切换或用户输入均拒绝粘贴。
- 保留所有剪贴板项目/格式，并仅在归属未变时恢复；粘贴后的用户新拷贝不会被延迟恢复覆盖。
- 成功路径不激活主窗口，保留来源 App 焦点。「打开选文」仍打开 App。
- 失败/成功 HUD 独立持久化开关，默认失败开启、成功关闭。提示不取得键盘焦点、不拦截鼠标，也不申请系统通知权限。
- 成功提示表述为「转换结果已发送至原应用」，不把 CGEvent 返回等同于宿主确认接受粘贴。

## 运行验证及失败记录

第一版错误地预先累计合成复制键，第二版又假定私有 source 不会影响会话计数；两种假设均被实际运行推翻，正常操作误判 `inputChanged`，未粘贴。原失败分别保存在 `fixed-first-attempt-results.json` 和 `session-counter-failure-lldb.txt`，不追溯改写为通过。最终改为硬件状态表，避免把自己的合成按键作为用户中断；同时检查按键/鼠标是否仍被按住，以覆盖计数不记录的自动重复输入。

沙盒探针直接编译工作区的生产事务和 HUD，只有转换结果使用独立预计算夹具。用户点击一次后串行测试，结果同时显示在提供者与宿主原生窗口中；宿主独立 `host-events.json` 保存实际文本变化。

| 场景 | 实际结果 |
| --- | --- |
| 正常复制、转换、再次核对选文、粘贴 | 宿主实际变为 `鼠标里面的软件，着衣与衞生纸。`，与独立 `tw2sp` 预期一致 |
| 转换期间剪贴板归属改变 | `clipboardChanged`，未粘贴；保留最新复制 |
| 宿主选文改变 | `inputChanged`，未粘贴；新选文保持不变。仅计为取消保护成功，不写成实测命中 `selectionChanged` |
| 切换来源 App | `sourceChanged`，未粘贴 |

随后换成完整 App（同一独立 Bundle ID、应用沙盒 entitlement、ad-hoc 签名），实际代码来自 `build-4`，以专用 ⌃⌥⇧⌘J 隔离正式 App 的 ⌥⌘T。设置页读回快捷键、已授予权限和启用状态。用户真实按键后，宿主实际变为 `滑鼠里面的软体，著衣与衞生纸。`，与独立 `t2s` 输出逐字一致。这次经过完整 KeyboardShortcuts 回调与实际 OpenCC 引擎，不是直接调用转换服务。

完整 App 结果见 `full-app-launch.json`、`full-app-expected.json`、`full-app-result.json` 与宿主日志。之后仅改 HUD 样式/文案；最终事务源码与成功运行探针逐字一致，SHA-256 和源码哈希见 `final-code-provenance.json`。最终编译为 `build-7-final`。

配置注意：命令行直接传 JSON 时，Foundation 会丢弃不能解析为属性列表的该项参数；测试首次显示默认 ⌥⌘T 后已关闭该实例，改为传入带属性列表引号的 JSON 字符串重新启动，并读回专用 J 组合。默认 T 状态下没有执行快捷键验收。不修改正式 App 绑定，不把测试参数写入产品代码。
