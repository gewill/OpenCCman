## 本轮实现

- 移除强制 AX 选区读取，使用不抑制本地输入的私有 CGEvent source 经 HID 发送复制/粘贴。
- 来源 PID 必须仍在前台；以硬件输入活动计数捕捉操作期间的键盘、点按、拖动、滚轮变化；等待超过 5 秒取消。
- 转换后、粘贴前再次复制完整选文并比较；剪贴板归属变化、无法复制、选文变化、来源切换或用户输入均拒绝粘贴。
- 保留所有剪贴板项目/格式，并仅在归属未变时恢复；粘贴后的用户新拷贝不会被延迟恢复覆盖。
- 成功路径不激活主窗口，保留来源 App 焦点。「打开选文」仍打开 App。
- 失败/成功 HUD 独立持久化开关，默认失败开启、成功关闭。提示不取得键盘焦点、不拦截鼠标，也不申请系统通知权限。
- 成功提示表述为「转换结果已发送至原应用」，不把 CGEvent 返回等同于宿主确认接受粘贴。

## 运行验证及失败记录

第一版错误地预先累计合成复制键，第二版又假定私有 source 不会影响会话计数；两种假设均被实际运行推翻，正常操作误判 `inputChanged`，未粘贴。原失败分别保存在 `fixed-first-attempt-results.json` 和 `session-counter-failure-lldb.txt`，不追溯改写为通过。最终改为硬件状态表，避免把自己的合成按键作为用户中断；同时检查按键/鼠标是否仍被按住，以覆盖计数不记录的自动重复输入。

## #341 审查修复与实机复核（2026-11-16）

PR #341 的审查（15 项）在同日逐项修正，并在本机做修复前后对比。本节取代上文几处描述：键盘按键不再计入输入活动计数（自身合成的 ⌘C/⌘V 会被晚到地计入）；成功提示仍为「已发送至原应用」；只读文字与剪贴板工具的边界见下文实测。

### 环境与方法

- 主机 macOS 27.2.1（26B131），Xcode 27.2；两块屏幕。后台常驻豆包输入法（DoubaoIme）和剪贴板工具 iCopy。
- 对比构建：修复前 `c935ec8`，修复后最终代码 `570c9f8`（其后 `fb1e9ea` 只加检查，`007fbe7` 只改成功提示文案，均未上机）。中间构建 `0d6c7a5`、`7861d8d` 的结果一并保留。
- QA 副本用开发证书签名，独立 Bundle ID `org.gewill.OpenCCman.ShortcutReview20261116`，前后构建共用一次权限授予。设置经启动参数传入（团队签名的容器拒绝 `defaults write`）。
- 测试快捷键 ⌃⌥⇧⌘T 从会话事件层发送。从 HID 层发送时，T 会在 HID 状态里短暂保持按下，事务按设计视为用户输入而取消；这是测试工具的问题，不是 App 故障。
- 宿主：TextEdit、Safari、Terminal、隔离数据目录的 VS Code，以及自制 KeyProbe（普通／只读／粘贴延迟 1.2 秒／复制后立即切走）。剪贴板变化、类型和标记由轮询记录；通用剪贴板按 `pboard` 日志的发送代次核对；VoiceOver 播报按 `AXAnnouncementRequested` 通知核对。

### 实机发现

- 本机输入法会读取每次剪贴板变化：任意进程写入由数据提供者延迟提供的文字后，0.15–0.35 秒内就被读取，带 `TransientType` 或 `ConcealedType` 标记也一样；系统日志显示读取方为 DoubaoIme。因此「有人读取了转换结果」不能证明目标 App 已粘贴。中间构建 `0d6c7a5` 以首次读取结束等待，延迟 1.2 秒粘贴的宿主仍贴进了被还原的旧剪贴板。最终改为粘贴后固定保留 1.5 秒（用户新复制时提前结束），只把「始终无人读取」当作宿主未接受粘贴。
- 同一原因，只读文字在本机不会转到 OpenCCman 显示，结果仍被丢弃，但剪贴板会还原、原文不变。App 内帮助、说明与提示改为建议只读文字使用「打开选中文本」。没有这类读取者时的转交行为只由回归检查覆盖，本机无法复现。
- 自身合成的按键会进入 HID 状态：C/V 显示为按下约 10–20 ms，keyDown 计数晚到地计入（1.15 秒时 +4）。修复前多个场景因此误报「输入变化或等待超时」。现在不计键盘按键，按住检测忽略 C/V；键盘修改由粘贴前的再次复制比较发现。
- 审查提出的「按住 ⌘⌥ 时合成 ⌘C 会变成 ⌥⌘C」被实测否定：物理按住 ⌘⌥ 时，宿主收到的合成 ⌘C 只带 ⌘。未加修饰键等待。

### macOS 27 的权限名称

macOS 27 把「隐私与安全性」中的辅助功能权限改名为 Device Control and Data Access，与「辅助功能／无障碍」设置面板区分。名称取自本机系统字符串（隐私与安全性面板、TCC 通知标题、授权提示）：简体「设备控制和数据访问」，繁体（台湾）「裝置控制和資料取用」；香港繁体为「裝置控制和資料取用權限」，按术语规范取台湾用法。设置面板本身在简体中改称「无障碍」，繁体仍为「輔助使用」。

App 内凡提到这项权限的文案在三种语言都有 macOS 27 版本，按运行系统切换。实机（简体）读回：设置页「已授予「设备控制和数据访问」权限」，帮助页三段与快捷键设置页说明均为新名称和新的只读文字说明。英文、繁体与 macOS 26 及更早的文案只由 `check-control-labels.sh` 覆盖，未在对应系统上运行。
