# #34 iOS import completion and error ordering (2026-09-25)

This is an isolated Simulator acceptance slice for OpenCCman 2.0, not closure
of #34. The source baseline was `develop` at
`4425781c5bdb4a7c98f91c40a3131c490d5ca017`. Xcode 27.0 (27A266a),
English, light appearance and default content size were used.

`scripts/check-whats-new-ui.sh` built an unsigned Debug app with the exact QA
bundle ID `org.gewill.OpenCCman.WhatsNewUITests`. Only that QA app's built
Info.plist enabled Files sharing. Its Documents folder received `success.txt`
(UTF-8 with CRLF, emoji and a combining accent; SHA-256
`0a680d94c8470e2d691f397a80677f0ce7aca17171dbe4e6bfdc8b34becc40b0`)
and `bad-encoding.txt` (invalid UTF-8; SHA-256
`b632bfa9c60bc17f7fd78dba311fd3f5dfa66cb8c017a4278e2bae28d668844d`).
No production file-sharing setting or installed store app was changed. A
Debug-only argument delayed the real import task by two seconds to expose its
presentation state; the file read and error handling remained real.

On a dedicated iPhone 15 Pro Max / iOS 18.6 Simulator, the complete What's New
UI suite passed: 13 cases, 0 failures, 1 existing iOS 27-only VoiceOver case
skipped. The final two import cases were rerun after strengthening the draft
preservation assertion: 2/2 passed. The success path selected the TXT through
the native Files picker, showed import progress without cards, replaced source
with the Chinese/emoji fixture, cleared the prior result, and then showed the
cards once. The invalid-UTF-8 path started with an actual edited draft, kept
that draft while showing the error alert without cards, and showed the cards
once after OK. The final interaction recording SHA-256 is
`7a79e5ab87764137b4a18f8dceac1f0eb4676e9e99f71879a6f190fbd4d2554c`.
The XCUITest `.xcresult` preserves the runtime screenshots; the PR attaches
selected screenshots and the recording with `gh`.

The dedicated iPad Air 11-inch (M4) / iPadOS 26.5 Simulator found the app's
test TXT files under Files > On My iPad > OpenCCman. In repeated attempts, both
single and double XCUITest taps on the TXT cell left the native Files picker
open; the app import completion callback was not reached. The iPad-specific
file-selection cases therefore skip explicitly, while import cancellation
remains in the existing suite. This does **not** establish an app import
failure for iPad users. The failed test logs and screen recording are retained
in the local validation directory, and #34 retains iPad selection acceptance.

The two-second QA delay does not validate a 10 MiB import, real foreground
first launch, iOS 15, physical devices, a signed TestFlight build, purchase
behavior, or VoiceOver narration. Those remain in #34 and related release
issues.
