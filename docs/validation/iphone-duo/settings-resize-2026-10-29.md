## 原失败及反证

Xcode 27.1 (27A9275)、Duo / iOS 27.1 (24A94425) 的实际观测：

| 状态 | App frame | XCTest window frame | Done frame | isHittable |
| --- | --- | --- | --- | --- |
| 初始外屏 | 466×678 | 466×678 | [399,179,38,38] | true |
| Resizable 宽态 | 950×669 | 316.67×223 | [248.5,13.33,12,12] | false |
| Resizable 窄态 | 400×750 | 133.33×250 | [112,13.33,12,12] | false |

缓存和重新查询的元素相同。原条件
`close.frame.midX > initialClose.midX + 100 && close.isHittable` 比较不同尺度的几何，
在本次环境不成立，解释了旧用例超时。未追查 XCTest 内部实现，不将三倍现象外推到其他环境。

进一步分离了两个问题：

1. 原始可点击断言在诊断中复现失败（16.340 秒）。
2. 早期坐标换算和标准 `tap()` 对照只检查底层工作区存在、稿件相同，
   **不能证明弹层已关闭**；其中 28.765 秒的通过是关闭判据不足的假阳性，不计入验收。
3. 增加 `Done.exists == false` 后，标准 `tap()` 失败（32.519 秒），
   日志记录 `Computed hit point {-1,-1}`；弹层仍在。换专用新设备后的
   normalized element-center 点击也失败（34.229 秒）。这些失败保留，不改写为通过。
4. 同一应用包改用 Device Hub 内实际指针操作，宽／窄均关闭；
   XCTest 独立等待 Done 消失，再逐字核对完整原文和转换结果。六项均通过。

由此，本次未复现“实际点击无法关闭设置／丢稿”的产品缺陷；
确认原几何判据不适用，且当前 XCTest 合成点击路径存在限制。
修复验收入口和断言，不因自动化路径失败添加产品坐标补丁。
