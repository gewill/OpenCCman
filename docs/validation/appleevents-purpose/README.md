# Remove the obsolete Apple Events purpose string

Issue: [#88](https://github.com/gewill/OpenCCman/issues/88), discovered during the [#17](https://github.com/gewill/OpenCCman/issues/17) metadata audit. Baseline: `dfac3649f23eb9d483ebefe9510a8da535ab372b`, checked 2026-09-15.

The generated Info.plist settings advertised permission to execute AppleScript, but current cross-app shortcuts use Accessibility checks, CGEvent and the clipboard. The app has no Apple Events automation entitlement. Searches of app and locked dependency Swift/Objective-C sources for `NSAppleScript`, `NSAppleEventDescriptor`, `AEDeterminePermissionToAutomateTarget` and `AESendMessage` found no calls. This source inspection does not constitute a new runtime shortcut test.

[Apple documents NSAppleEventsUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription) as the purpose message for APIs that send Apple events. It is not the purpose string for Accessibility or Services. Both Debug and Release now omit this unused generated-plist key. The existing Accessibility flow, keyboard shortcuts, Services, entitlements and dependency lockfile are unchanged.
