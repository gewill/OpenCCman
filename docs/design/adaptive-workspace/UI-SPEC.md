# UI 与交互规范

本文与 [画稿](README.md)、[实施计划](PLAN.md) 配套。状态是**待实施设计**；具体数字为本项目首轮布局预算，需真实英文、简繁与大字号验收，不能宣称来自 Apple 的固定间距标准。

## 1. 核心结构

```text
窗口 / 页面
  工具栏：转换设置入口、标题、布局（宽屏）、转换/取消、既有设置入口
  工作区
    可隐藏的转换设置侧栏（足够宽时）
    原文编辑器 + 结果只读编辑器（左右或上下）
  占位参与布局的额度/推荐区（非 Pro；键盘弹出时让位）
```

这里的侧栏是**转换参数检查面板**，不假装成文件导航或新增功能入口。四预设与三组高级选项继续通过 `ConversionConfiguration` 映射，保留原偏好键、简体禁用两组高级选项及“自定义”显示。

原文可编辑，结果只读但可选中和复制。复制按钮复制当前有效的完整结果，系统文字选择继续支持复制选区。两份文本各自滚动，不默认同步滚动；本轮不加入差异标记、行号、历史、批量、OCR、统计面板或自动转换。

## 2. 画板和控件预算

下表是逻辑 pt 的设计目标，PNG 的实际像素尺寸见 manifest，不应从生成图反推精确约束。

| 画稿 | 目标逻辑画板 | 重点 |
| --- | --- | --- |
| M01 / M02 | 1440 × 1024 | Mac 左右/上下、侧栏、拖动比例、浅深色、非 Pro/Pro |
| P01 | 1194 × 834 | iPad 宽窗口、侧栏＋左右 |
| P02 | 834 × 1194 | iPad 竖向、隐藏侧栏＋上下；可主动左右 |
| P03 | 600 × 900 | iPad 多任务窄窗口、上下回退、工具栏折行 |
| F01 / F02 / F03 | 390 × 844 | 手机主页、参数面板、键盘 |
| S01 | 1440 × 1024 | 六类操作状态组件示意 |

- 沿用现有 `Constant`/Neumorphic 语义颜色及分段样式，新增尺寸收敛到一处布局指标，不散落魔法数字。
- 普通布局以 12/16/24 pt 分组和边距作为设计预算，安全区与系统工具栏由系统管理。必要时使用系统默认间距；不把画稿的阴影厚度当成内容 padding。
- Mac 侧栏初始宽 264 pt、iPad 248 pt；建议约束 240–320 pt，长标签或大字号改为纵排/滚动。隐藏侧栏时完整释放占用宽度。
- 普通字号左右每个文本 pane 最小约 320 pt；上下模式每个 pane 的可读正文高度目标至少 180 pt。达不到时切换到可滚动单列，不把正文压成几行。
- 自定义控件按完整占位计算：内容、padding、背景、向内边框及阴影均包含在内。Mac 普通图标/文字按钮与 Segment 默认高 28 pt，主操作 32 pt；iPhone/iPad 默认为 44 pt。Segment 单项最小宽度同平台默认高度。图标默认 Mac 14 pt、触屏 18 pt；文字采用语义字体，大字号/多行自然增高。
- Mac 每边预留 2 pt、触屏 4 pt 给阴影；只裁剪装饰，命中区域覆盖完整占位，按压动画不缩小命中区。系统控件保留系统尺寸，多行信息卡片不压成按钮高度。依据与实际运行证据见 [控件尺寸修正](../../validation/control-sizing/README.md)。
- 中文正文：手机/iPad 以系统 body（普通字号约 17 pt）为起点，Mac 约 16–18 pt；正文 regular，标题 semibold。支持系统缩放，不以全局字号上限来避免溢出。
- 长文本使用编辑器本身的滚动和自动换行；不为了测量文字尺寸反复复制或布局 10 MiB 正文。
- 视觉层级使用间距、文字和分隔线优先，阴影只表达轻微凹槽/控件层级；高对比度不能仅靠阴影识别边界。

## 3. 布局偏好与宽度回退

### 状态模型

建议新增独立纯值 `WorkspaceLayoutPreference` / `WorkspaceLayoutResolution`，区分：

- `preferredAxis`：用户选择的左右或上下；未选择时为空。
- `effectiveAxis`：根据窗口和无障碍条件算出的实际布局。
- 侧栏偏好与实际可见性分别保存，自动隐藏不覆盖用户选择。
- 左右和上下各自保存 source/result 比例；初始 0.5，建议范围 0.3–0.7，同时满足最小 pane 尺寸。

窗口拥有自己的布局状态，不把它放入共享转换配置，也不使用一个全局 `@AppStorage` 令所有窗口同时跳动。优先使用最低系统支持的窗口状态保存机制，例如 `@SceneStorage`；恢复失败或新窗口没有记录时根据可用空间选择默认值。正文不作为布局偏好持久化，重启文本恢复不在本轮承诺内。

### 首轮可执行规则

测量 **W = 编辑器区域宽度**（扣除安全区、外边距和实际侧栏）。依据当前窗口，不用 `UIScreen.main.bounds` 或设备名称。

1. iPhone 常规紧凑界面固定上下，不显示无用的左右切换；横屏仍采用可滚动上下，避免两个低矮编辑器。未来新的 regular 场景需独立验收再开放。
2. Mac/iPad：W ≥ 760 pt 时可进入左右；已经左右时允许保持到 W ≥ 720 pt，低于 720 则回退上下。40 pt 的缓冲用于避免临界尺寸反复跳动，最终数值以验收修订。
3. 未选过布局时：满足宽度则默认左右，否则上下。已选上下时，扩大窗口不会擅自切成左右。
4. 已选左右但空间不足：实际显示上下，左右入口禁用并提供“窗口较窄，暂以上下显示”；恢复到进入阈值时恢复左右。
5. 总宽度约 1100 pt 以上可默认显示侧栏；更窄默认隐藏。用户主动显示侧栏时重新计算 W，必要时回退上下。侧栏不能遮住编辑器当作固定栏；窄屏使用可关闭的系统面板。
6. 辅助功能字号优先上下＋纵排选项；此回退不改变已保存偏好。退出大字号后按窗口宽度恢复。
7. 内容高度不足（小 Mac 窗口、横屏手机、键盘）：单列可滚动，转换/取消和当前输入光标始终可达；不强制保持 50:50。

临界测试覆盖 W = 719/720/759/760、连续缩放、隐藏/恢复侧栏和尺寸变化期间的任务。阈值只决定布局，不能计次或启动业务操作。

### 切换交互

Mac/iPad 工具栏使用图标＋文字的一体式 segment：“左右”“上下”，选中背景蓝、白字并带可访问选中状态；Mac 的 View 菜单提供等价命令。不使用图标歧义很大的“横向/纵向分隔线”命名。

切换必须保留原文、结果、文件名、有效导出快照、进行中的任务 ID、额度预约、输入光标/选区、编辑焦点和两份正文的滚动位置。不调用 `translate`、`replaceSource`、`cancelConversion` 或 `cancelImport`，不触发 RootView 的页面退出副作用。

方向变化时，滚动位置按段落/字符锚点尽量恢复，不能机械复用另一宽度下的像素 offset。若现有 `TextEditor` 无法证明此行为，先在组件层做最小验证；需要原生包装时隔离在编辑器适配层，不能宣称仅换 HStack/VStack 就已验收。

分隔线支持鼠标/触控拖动、键盘和 VoiceOver 调整；提供“恢复均分”菜单项作为不拖动的替代。Mac 拖动带为 16 pt，iPad 为 44 pt，布局计算同步扣除对应宽度；不把整条透明覆盖层放到可编辑正文上。手机不提供比例拖动。默认过渡简短，Reduce Motion 下立即切换，不连续播动文本。

## 4. 三端信息层级

### Mac

- 使用系统窗口和工具栏；保留已有设置、帮助、Pro 入口及 `⌘,`、`⌘T` 等快捷键，不绘制自制红黄绿控件。
- 工具栏从左到右：侧栏开关、应用/文档标题、布局、转换/取消。设置/帮助可依宽度进入菜单，但不能移除现有访问路径。
- 原文 pane：标题/文件名、粘贴与导入、编辑器、简短格式提示；结果 pane：状态、复制与导出、只读结果。
- 每个 pane 独立滚动，不再让整页 ScrollView 把结果推到屏幕下方。
- 300 pt 宽仍可操作：侧栏隐藏、工具栏换行或溢出菜单、上下滚动；不得因为宽屏设计随意提高应用最小窗口宽度。
- 无有效历史尺寸时，主窗口以 1024 × 768 pt 为推荐初始内容矩形；已有原生窗口历史优先。这里采用 `NSWindow.contentRect(forFrameRect:)` 口径，完整尺寸内容窗口的标题栏仍占用其内部空间。
- SwiftUI 根内容区最小为 300 × 360 pt，不包含系统标题栏。macOS 27 实测标题栏为 52 pt，实际最小窗口为 300 × 412 pt；标题栏高度由系统决定，不硬编码 412。推荐尺寸下根内容区为 1024 × 716 pt。低高度时滚动访问原文、结果和推荐区，主操作保留在顶部。
- 窗口位置和完整外框受所在屏幕可用区域约束；换屏、分辨率变化、退出全屏和结束 sheet 后重新校正。新增窗口沿用系统级联位置，尺寸调整不替换业务模型。证据和未完成边界见 [窗口尺寸验收](../../validation/window-sizing/README.md)。

### iPad

- 使用同一组组件；侧栏按窗口宽度显示，竖屏/多任务可从转换设置入口打开系统面板。
- 上下/左右切换与 Mac 共享状态语义；不是横屏锁左右、竖屏锁上下。
- P01/P02/P03 分别展示宽窗口、竖向与多任务。原文支持系统文件导入及拖放，仍只接受单个 TXT/文本，不新增跨 pane 拖放转换功能。
- 键盘出现时只收起推荐和必要辅助信息；不强制清空结果或关闭转换。硬件键盘保持系统焦点顺序、⌘T、⌘,；没有硬件键盘时不常驻显示 ⌘ 提示。
- 系统分屏、Stage Manager/窗口缩放按实际可用系统验证；不增加对新系统窗口 API 的无条件依赖。

### iPhone

- 精简页头和预设摘要；转换设置作为 sheet，四预设以可访问列表展示，高级选项复用分段控件。完成只关闭面板，选择立即生效且不自动转换。
- 原文在上、结果在下，用可滚动页面承载；不强行在每种尺寸和字号同时显示全部正文。转换/取消处于参与布局的底部操作区。
- 低频导入/导出可放入 pane 的“更多”菜单，粘贴/复制保持直达；菜单项同样有完整文案，不仅图标。
- 键盘出现后推荐隐藏，唯一转换按钮移到键盘上方的操作区，提供“收起键盘”；不能同时显示第二个转换按钮。
- 键盘区域参与内容 inset，光标、选区及错误恢复操作不被遮住。不在根视图忽略键盘安全区来维持旧布局。
- 收起键盘或完成转换时可显示结果，但不能无条件抢夺焦点或打断输入法 marked text。中文组合输入期间的键盘/旋转行为列入验收。

## 5. 任务和结果状态

| 状态/事件 | 显示 | 可用操作和数据规则 |
| --- | --- | --- |
| 无输入 | 原文占位；结果“尚未转换” | 粘贴/导入可用；转换、复制、导出禁用。当前应用预填示例保持不变，空白图只表示用户已清空后的状态 |
| 有输入待转换 | 原文可编辑；无新结果 | 转换可用；复制以 `resultText` 为准，导出以 `exportSnapshot` 为准 |
| 导入中 | 保留旧稿，显示读取进度环与取消导入 | 编辑/新导入/转换暂不可用；显示可用旧结果时明确它尚未被替换。布局切换可用，不取消读取 |
| 导入失败或超限 | 系统错误提示，说明具体原因和原文保留 | 解除导入锁定；原稿、文件名和旧结果保持，不扣次；系统选择器取消不报错 |
| 导入成功 | 替换原文/文件名，清空旧结果 | 取消旧任务并清空旧快照，旧任务不能回写；保留布局/滚动恢复策略但新稿从顶部显示 |
| 转换中 | 不定进度环；转换按钮替换为取消 | 任务使用开始时的文本/选项快照；不显示伪百分比。编辑原文仍按已有逻辑取消旧任务。布局切换不取消 |
| 成功 | 新结果、已完成 | 复制/导出可用；成功提交一次预约，布局或导出不计次 |
| 取消/转换失败 | 显示已取消或具体错误，原文保留 | 立即停止结果回写、释放预约；不宣称中断正在执行的 C++；可重新转换 |
| 无新结果但有旧导出快照 | “本次没有新结果，可导出上次成功结果” | 当前复制禁用；“导出上次结果”可用。新输入/成功导入已清空快照时不能显示此状态 |
| 修改输入 | 清空结果和快照 | 延续 `HomeViewModel.inputText` 现有取消/失效语义，不能留下看似有效的旧导出 |
| 修改预设/高级选项 | 明确设置用于下一次转换 | 当前代码不会自动重算/清空旧结果；显示“设置已变更，结果来自上次转换”。记录本次任务/结果配置来源，避免旧结果冒充新设置输出 |
| 日额度用尽 | 现有额度提示与 Pro 路径 | 可以编辑、导入、导出、切换布局；主页新转换走既有额度门禁，不新增收费条件 |
| Pro | 既有资格对应的状态入口，无推荐 | 不新增全局次数统计或商品价格；资格恢复/购买保持原流程 |

**配置来源提示是本轮新增的展示状态**，不能借机改变选项生效、取消、收费或引擎策略。任务中切换预设时，显示本次仍使用启动配置、下一次使用新配置；业务快照仍由原模型管理。

导出使用系统文件保存面板，默认 `<原名>-converted.txt` 或 `OpenCCman-converted.txt`，UTF-8 无 BOM；取消不报失败。错误文案区分非法 UTF-8、超过 10 MiB、多文件、读取/保存权限，不统一为一个模糊提示。S01 的复合说明只作画稿示意。

布局持久化只保存界面偏好，不新增本地文本历史。字符示例是排版素材，不作为 OpenCC 词库回归预期；引擎行为以已有固定语料与真实转换为准。

## 6. 推荐区与额度

复用 #40 修复，不另开重复缺陷单。把 `HomeScene` 的独立覆盖层改为参与布局的 footer 或低高度时的滚动内容；去掉 `MyAppView` 固定 300 pt 宽度和负 offset。

现有“×”调用 `/pro`，新文案为“移除推荐”，点击继续走原 Pro 页面；不能在此次布局优化中静默改成免费关闭。保留真实推荐资产、目标链接和既有轮换规则，不用生成图中的图标/宣传语替换产品资料。

普通字号显示紧凑推荐行；大字号允许纵排并进入滚动内容，不能固定高度裁切。键盘出现时暂时隐藏推荐及非关键额度文字，收起后恢复；Pro 始终不显示推荐。推荐区不能抢走键盘焦点或在 VoiceOver 阅读时因轮换改变焦点。

图中的“今日剩余 8/12”是示例状态；实现复用现有额度来源并考虑活动预约，禁止写死、另建计数器或因窗口重排重复预约。

## 7. 兼容性与实现边界

- 保留 iOS 14 / macOS 11；Neumorphic、OpenCC 和其他依赖版本不在本轮升级。
- 不以 `NavigationSplitView`、`ViewThatFits`、新 `Layout` 协议或新 sheet detents 作为最低系统必需实现；新 API 只能有明确 availability 分支和已测回退。可评估 macOS `HSplitView`/`VSplitView` 或小范围原生适配，iPad 用兼容容器。
- iOS 14 的 sheet 用系统全高度回退；新系统可使用系统允许的呈现形式，但完成按钮及参数语义不变。画稿把手/圆角不代表必须调用某个新 API。
- `RootView` 继续拥有稳定的 HomeViewModel 和 WhatsNewWindowState。文件导入/导出与 What’s New/Pro/错误互斥规则保持，不在 pane 的 onDisappear 中注销业务任务。
- 验证是否需要封装 NSTextView/UITextView 以保持选区、滚动和焦点；只有实际不满足时才增加适配，不先大改编辑引擎。
- 日常 PR → `develop`。正式包仍通过明确的临时 `build*` 分支触发 Xcode Cloud，旧 `build` 引用退出问题独立跟踪；本设计/计划 PR 不打包、不部署。

## 8. 必须通过的验收矩阵

| 维度 | 场景与期望 |
| --- | --- |
| Mac | 1440×1024、1024×768、300 pt 窄窗口、低高度；两轴、侧栏开关、比例拖动、菜单和快捷键可用 |
| iPad | 1194×834、834×1194、600 pt 与约 375 pt 多任务窗口；横屏上下/竖屏左右均测；旋转及缩放不丢状态 |
| iPhone | 320/375/390/430 pt、横屏、键盘展开/收起、中文输入法 marked text；转换和取消可达 |
| 字体与外观 | 英语/简体/繁体，默认至最大辅助功能字号，浅/深色、高对比度、Reduce Motion/Transparency |
| 窗口与状态 | 两窗口不同布局/不同稿，切换布局50次；导入中、转换中、错误提示中、系统文件面板中、What’s New 待显示时切换/缩放 |

## 9. 依据

当前代码证据位于基线 `fbd1ac0`：HomeScene 的大块参数区、整页滚动和推荐 ZStack；RootView 的模型所有权及 `.ignoresSafeArea(.keyboard)`；MyAppView 固定宽/负 offset/Pro 路由；HomeViewModel 的任务与导出快照语义。#40 和 #37 提供已复现的大字号与设备验收记录。

Apple 的 [Split views](https://developer.apple.com/design/human-interface-guidelines/split-views) 支持多 pane、合理最小尺寸及必要时隐藏辅助 pane；[Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 与 [Windows](https://developer.apple.com/design/human-interface-guidelines/windows) 指导依据可用窗口适配。这里采用这些原则，但侧栏宽度、720/760 阈值和 0.3–0.7 比例是项目候选参数，待真机验证。用户选定的 Neumorphic 外观保持；不把“类似原生”当成已经通过 HIG/无障碍验收。
