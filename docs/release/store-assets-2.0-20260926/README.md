# OpenCCman 2.0 App Store screenshots

These are real OpenCCman UI captures for the iOS, iPadOS, and macOS 2.0 App Store drafts. The capture source is `2f782714103d68b4972bee93e47bda8cafee1959`, the source used by Xcode Cloud Build 56. A locally built, unsigned QA variant with bundle ID `org.gewill.OpenCCman.StoreShotsQA` was used to avoid changing the installed TestFlight app. Its internal build number is 30; the signed ASC build is 56. This establishes matching application source, not signed-build runtime acceptance.

The storyboard follows the [App Store screenshot prompt guide](https://github.com/gewill/dev-standards/blob/main/app_store_screenshot_prompt_guide.md). The first workspace image shows the initial Simplified Chinese sample and its actual OpenCC Traditional result together, so the user can see the task, change, and proof in one genuine app state. The following image shows choice of presets or the alternate layout. We kept the set small because additional nearly empty editor images would repeat the same claim. No performance, rating, or Pro-only claim was added to the pictures.

The sample text is `鼠标里面的硅二极管坏了，导致光标分辨率降低。`, converted with the OpenCC Traditional preset. It is demonstration content, not a customer document or a performance measurement. In-app recommendations are below the photographed workspace; the screenshots do not imply that a free user has no recommendations.

`manifest.json` records each current image's SHA-256, original MD5, dimensions, bytes, ASC screenshot ID and processing state. The original 2023 ASC assets are preserved in `previous-asc/` with SHA-256 hashes before replacement. On 2026-09-26, `asc screenshots upload` replaced the 6.9-inch iPhone (`APP_IPHONE_67` API slot), 13-inch iPad and Mac slots in all three locales. The 2023 5.5-/6.5-inch iPhone and old 12.9-inch iPad assets were then removed; their set objects remain empty in ASC. An API readback found **15 current assets**, all `COMPLETE`, with remote source MD5 equal to the local files. No old screenshot remains in a populated set.

The ASC CLI readiness validator reports nine `screenshots.required.set_nonempty` errors for those three empty historical set objects per locale, despite the populated modern iPhone and iPad sets. The signed-in ASC UI displayed the modern screenshots as inherited by older sizes, accepted both platform versions into review drafts, and accepted final submission; both submissions read back as `WAITING_FOR_REVIEW`. Thus these CLI errors did **not** block this actual submission. Do not repopulate old slots with outdated UI merely to silence the CLI; revisit if Apple review raises an issue.

This visual review covered the full-size English, Simplified Chinese and Traditional Chinese screens, sample conversion state, modal completion and the supported pixel sizes. It did not include a native-speaker copy test, user-comprehension study, conversion experiment or signed-build visual comparison. The English Mac capture contains a macOS purple window-sharing indicator in the title bar; it is a capture-environment artifact, not product UI, and should be replaced if ASC review flags it or before the public page is finalized.
