# 2.1 当前源码应用基准（#18）

本记录固定 `develop@158595d49b8c6af53641c95af1518e76f022743f` 的 Release 应用诊断结果，为后续 2.1 改动提供可复测的基线。运行入口是 [App Regression #36468671581](https://github.com/gewill/OpenCCman/actions/runs/36468671581)，其 `Release application performance baseline` job、来源及样本完整性检查均成功。没有更改产品代码，也没有触发 Xcode Cloud 发布。

## 方法与来源

- GitHub `macos-15` runner：macOS 15.7.9 (24G830)、Apple M1 (Virtual) / VirtualMac2,1、7 GiB、Xcode 26.3 (17C529)、arm64；Release `-O`。五个独立新进程依次运行相同协议 2，未清空系统或文件缓存，也未删除首轮慢样本。
- 固定英语、浅色、1200×800 pt 诊断窗口，覆盖首次转换、五次热转换、七组配置、1/5/10 MiB 和两轮托管额外窗口。`metadata.json` 固定源码、依赖 revision、测量条件与源码哈希，`build-complete.json` 记录产物哈希；五份 `run-*.json` 与 `summary.json` 保存原始和汇总数据。完整构建日志在该 CI run 的 14 天 artifact 中，不提交可能含云端环境细节的日志。
- `scripts/compare-app-performance.py` 的加载校验与 CI 独立校验均通过：每份样本状态为 `complete`、36 个相同阶段、七组有效配置；同阶段输入和输出哈希跨五次一致；编辑器、模型和导出逐字节一致；前台可见窗口与内存采集状态有效。两轮关闭托管额外窗口后，五份样本的额外模型存活数均为 `[0, 0]`。

## 解释与待办

“根布局就绪”包含 LaunchServices reopen 握手，并非冷盘启动、首帧像素或用户可交互时间；转换计时止于模型完成，诊断布局 flush 也不等于结果实际呈现。隔离 App 使用 ad-hoc 签名、关闭 sandbox、合成 Pro 资格，保留 RevenueCat configure 但抑制部分网络／弹窗；额外窗口是托管窗口，不替代生产 `WindowGroup`。本记录没有测量帧率、电量、真实购买、签名 TestFlight 用户体验或 1 GiB Pro 流式文件路径。

[2026-09-16 CI 基线](../integrated-baseline.md)与本轮虽使用相同 runner 类型和 Xcode，但期间 RevenueCat 与 SwiftyOpenCC revision 均变化，且不是同一台物理机器；[2026-09-24 本机基线](../2026-09-24-current-source-baseline/README.md)则使用 macOS 27 / M4 Pro。不要用这些不同条件的数据直接计算升级收益或断言回归。#18 仍需同机成对测量、最终签名包端到端呈现与大文本内存定位。
