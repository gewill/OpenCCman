# PR #66：测量协议修正与新基线

旧版编辑器计时包含全文字符串比较，撤回“651 ms 是结果显示成本”“主要成本移向文字显示”以及相关端到端合计结论。旧版 70.3% CPU 差异主要集中在手动托管窗口关闭之后，不能推广为日常编辑收益。[旧数据与更正](../2026-09-14/README.md) 保留历史原样，不手动修改 metadata 来通过新比较器。

- 应用与测量入口来源 `9603bf3480b7127ae4bc372938ec240114719f23`；正式应用源代码未在 #66 中改变。独立诊断 bundle、ad-hoc 签名、测试权益与 SDK 抑制边界见 [协议](../README.md)，不等同 TestFlight 签名包或系统默认冷启动。
- 旧 wrapper `53f200cebe40eade3ebda025b0e8980e08cf23fa` / OpenCC 1.2.0；当前 wrapper `6eded293f5c84c064f332cbc2832391165c82dda` / OpenCC 1.4.2。无其他依赖漂移。
- 三组各 5 个新进程，按旧引擎→当前引擎→当前引擎关闭闲时布局交错运行；每进程完整协议相同。全部构建、回归先完成再串行采样，计时期间没有录屏、AX 查询或 profiler。[实际采样顺序](sample-order.json)。全部 15 个正式运行完成并通过前台、内容及来源检查，未按耗时筛选样本。
- 一个旧驱动校准样本及失败的试验准备没有混入正式数据；修复唯一注入锚点后全组重新构建，详见 [校准说明](validation/calibration-note.json)。

## 修正后的时间指标

以下单位为 ms，格式为中位数 [最小值–最大值]。`model_completion_ms` 是真实模型转换完成发布；后续编辑器指标只计长度应答与刷新，长度预计算和精确内容验证在其计时区间之外。结果可能已经在之前的模型更新或调度阶段进入编辑器，因此接近零的后续刷新值不代表整段文稿瞬间绘制完成。它们不是屏幕呈现时间，也不能直接相加称为用户端到端等待。

| 指标 | OpenCC 1.2.0 | OpenCC 1.4.2 |
|---|---:|---:|
| 新进程至主页布局（含握手） | 524.3 [504.6–1,641.4] | 462.8 [434.3–1,661.7] |
| 256 KiB 首次模型转换 | 76.1 [63.7–121.9] | 55.0 [47.2–90.5] |
| 1 MiB 模型转换 | 178.7 [171.3–179.8] | 35.7 [29.8–46.9] |
| 5 MiB 模型转换 | 821.4 [811.1–826.2] | 110.8 [105.3–120.0] |
| 10 MiB 模型转换 | 1,623.0 [1,612.7–1,635.2] | 208.9 [202.3–209.6] |
| 10 MiB 原文替换至长度应答与刷新 | 514.1 [511.1–521.2] | 504.9 [501.8–523.2] |
| 10 MiB 结果的后续长度应答与刷新 | 0.2 [0.2–24.6] | 12.8 [0.2–17.6] |

模型转换路径在该固定语料上有明确改善。编辑器与启动指标应保留上述边界及完整范围，不再用后续刷新计时判断全部显示成本或定位主瓶颈。输入/输出跨引擎哈希一致；七组配置现使用七个不同的固定输出，包含台湾词组、台湾与香港字形，并验证 CRLF、空行、Emoji、组合字符和 U+0000。

## 闲时布局试验：按关闭阶段拆分

只改变隔离快照中的 `backgroundLayoutEnabled`。比较的是手动 NSWindow/NSHostingView 诊断路径，不能当作生产 WindowGroup 生命周期。下表单位为 CPU ms，先对每个运行相邻事件作差，再取中位数与范围；不是两个累计中位数直接相减。

| 阶段 | 当前引擎默认闲时布局 | 关闭闲时布局 |
|---|---:|---:|
| 第 1 轮：close 调用及移除 contentView | 7.4 [7.4–8.0] | 9.5 [8.0–10.6] |
| 第 1 轮：close 返回后的处理及固定等待 | 8,104.1 [8,014.7–8,202.5] | 60.5 [57.8–61.9] |
| 第 2 轮：close 调用及移除 contentView | 7.6 [6.8–7.7] | 9.9 [8.7–11.2] |
| 第 2 轮：close 返回后的处理及固定等待 | 8,002.1 [7,939.8–8,164.2] | 56.4 [55.5–58.5] |

长开销集中在 `close()` 返回后进入主线程后续处理的阶段；本协议没有单独对这段新运行做 profiler，不能进一步断言具体释放函数或称为泄漏。该阶段也包含两个 250 ms 固定等待。自动阶段区分支持继续调查此路径，不能据此声称打字、首屏显示或所有交互改善某个百分比。#65 / #67 的实际滚动与布局修复仍单独验证。
