# #68: 原生单编辑器的清空后内存回落对照

在不使用 SwiftUI、转换模型、结果编辑器或滚动保持器的原生 `NSTextView` 中，同一份 1 MiB 文稿清空 30 秒后，TextKit 2 的物理内存占用中位数仍高于 TextKit 1：**169.3 MiB 对 52.1 MiB**。各组三个新进程的范围没有重叠。这说明本协议中较高的回落值不以应用桥接为必要条件；但它**不能解释** [应用双编辑器实验](../2026-09-24-recovery-retention/README.md)的高、低两种状态，也不能单凭进程内存判断具体对象归属或泄漏。正式应用仍使用优化后的 TextKit 1。

## 同源对照

原生驱动提交为 `252d7e7cd6a35746f0bac46a894a39672d0fcf0a`。Apple M4 Pro / 48 GiB、macOS 27.0 (26A428)、Xcode 27.0 (27A266a)，`swiftc -O -g -target arm64-apple-macos12.0` 编译独立 AppKit 诊断包并进行 ad hoc 签名验证。**目标参数为 macOS 12 并不证明已在 macOS 12 运行。**

语料是 1,048,576 字节、402,196 个 UTF-16 单位的单个无换行段落，包含中文、家庭 Emoji 和组合重音；其 SHA-256 `3589430ad438ead1803658c8c0d77d32d30f5694b0b1787ffc512d4e32f8b239` 与应用实验输入逐字节相同。原生编辑器可用视口宽 440pt，等于应用实验最后一次横向布局的原文视口宽。原生窗口高 800pt，每个进程只有一个可见编辑器；依次完成首显、开头／中部／文末滚动，确认目标进入视口后清空文本，观察 5 秒和 30 秒。三组按 TextKit 1 → TextKit 2 交错运行，每次为新前台进程。

| 物理内存占用，MiB | 原生 TextKit 1（n=3） | 原生 TextKit 2（n=3） | 应用 TextKit 1（n=3） | 应用 TextKit 2 + #169（n=6） |
| --- | ---: | ---: | ---: | ---: |
| 清空前中位数 | 235.5 | 319.8 | 353.1 | 522.8 |
| 清空 5 秒中位数 | 54.4 | 173.6 | — | — |
| 清空 30 秒中位数（范围） | 52.1（51.1–58.2） | 169.3（167.7–170.0） | 212.2（197.3–226.3） | 381.7（189.2–383.4） |

原生六次运行全部完整、窗口可见且全程前台；`textLayoutManager` 在 TextKit 2 中存在，没有兼容模式回退通知。每次清空后的 `editor.string` 与 `textStorage` 均为零长度，滚动目标曾被确认可见。原生 TextKit 2 的 30 秒 RSS 仍为 290–293 MiB，因此这里采用物理内存占用报告回落，**不把 RSS 或物理占用本身解释为泄漏**。

应用列是前一报告的原始数据，由本报告的校验脚本重新读取：它有两个编辑器、转换结果、布局切换和 SwiftUI 桥接；其内容和阶段协议与原生程序不同。表中四列不能相减来计算“桥接开销”，也不能把应用 TextKit 2 的 2/6 次低状态解释为仅有一个编辑器缓存。此前应用高状态的两条引用树确实经各自的 `NSTextView → NSTextLayoutManager` 到达旧 `CTRun`，但本轮没有原生单编辑器的对象引用快照，仍需补齐对象类别、生命周期和双编辑器控制实验。

## 复核与边界

[`raw/`](raw/) 保存六份逐阶段运行数据、三份构建元数据、三份驱动汇总、压缩的原始输入及 SHA-256 清单。校验脚本复查构建源码提交、驱动哈希、同字节输入、440pt 视口、前台状态、TextKit 模式、清空后的双重文本长度、统计量，并重新验证应用归档：

```bash
python3 docs/performance/2026-09-24-native-recovery-control/analyze.py
python3 scripts/measure-native-textkit.py --output /path/outside/repo --pattern app-mixed --sizes 1 --samples 3 --modes tk1 tk2 --recovery --activate-process --content-width 440 --timeout 120
```

驱动以实际 PID 请求 System Events 将它刚启动的诊断包置于前台；如果权限或激活失败，前台校验会拒绝该次运行。正式六次数据分别保存在三个独立输出目录，而不是一次 `--samples 3` 调用；上述命令使用同一交错协议，可重新采样，不保证得到相同数值。预备试跑中曾发现 AppKit 程序单靠包名激活时保持后台，故这些试跑没有计入正式数据。运行前后没有修改 VoiceOver 或其它辅助功能设置。

本次仅覆盖 macOS 27 的单一合成语料、单编辑器和清空后 30 秒。下一步应使用同宽双原生编辑器分别载入原文／转换结果并获取 TextKit 2 高、低状态的 heap／VM 对象快照，再覆盖普通 TXT、重复 5/10 MiB、编辑／IME、iOS 15／macOS 12、VoiceOver 及签名包。#68 继续开放。
